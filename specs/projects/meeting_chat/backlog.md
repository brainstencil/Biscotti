  The functional spec says turning on the live transcript from the chat field catches up from the start of the recording, so chat can answer about the earlier discussion.   - **Decision (2026-10-29):** fix — turning the live transcript on mid-recording, from chat or from Settings, always catches up from the start of the recording, with no button. - [x] **B10 — Make the model wait shorter and honest: a "keep ready" setting, load on focus, and two distinct waits**
  The user's hands-on check (30 October 2026): the first question showed "Loading the AI model…" with a small spinner for about 30–60 s (Gemma 4 12B on an M1 Max). Today the model loads on the first question and closes 180 s after the last answer (`ChatResourcePolicy.idleKeepAlive`), or after each answer during a recording on Macs under 24 GB, so a later follow-up waits for the full load again. Proposed by the user:
  - **A setting to keep the model ready** (loaded at launch and kept), for people who want instant answers and accept its memory; off by default, so others load it when they start a chat. Settings should state the memory cost.
  - **Two waits, shown differently.** (1) Loading the model: a long wait with a measurable rate. Interface Lineage (honest-vs-theater-progress, skeleton-screen, pace-feedback-to-perception) says a wait over 10 s needs a real estimate, so a determinate bar fits; a bare spinner is that pattern's failure case. A real bar needs `LocalLLM` to report load progress, which this project kept unchanged (it would reset the `llm_*` manual tests). The chat-only alternative reports measured facts: elapsed time, and the last load's time on this Mac. (2) Time to first word (measured 3–20 s cold in phase 6): acknowledge at once in the answer's slot (typing-indicator-three-dots, acknowledge-before-you-finish), then stream (token-streaming). A skeleton does not fit: chat answers have no known layout, and a skeleton looks the same at 3 s as at 30 s (skeleton-screen; no-theater).
  - **Start loading when the question field gets focus**, not on Send, so part of the load overlaps typing (manager's proposal, not from the library).
  - **Decide:** whether to allow the `LocalLLM` change for a real load bar; the setting's name, default and placement; whether this goes with the B9 build or before it.
  - **Decision (2026-10-30):** no `LocalLLM` change: an estimated bar that fills against the last measured load on this Mac (the user chose it). "Keep the AI Model Ready" in Settings › AI Enhancements, off by default; the recording memory rule wins on Macs under 24 GB. Built now, before B9.
  - **Route:** task run
  - **Status:** closed — see the commit "Load chat's AI model ahead, show an estimated load bar, and add "Keep the AI model ready""

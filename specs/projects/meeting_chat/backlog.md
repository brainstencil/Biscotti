# Backlog: Meeting chat

- [ ] **B1 — Chat's "Turn On" does not catch up the live transcript from the start of the recording**
  The functional spec says turning on the live transcript from the chat field catches up from the start of the recording, so chat can answer about the earlier discussion. The code starts live transcription from the moment of Turn On (`turnOnLiveTranscriptForChat()` calls `liveTranscription.setEnabled(true)`, which starts a session from now; the pump drops audio before its start time, and the live tap keeps only about 128 blocks per track). A real catch-up would have to transcribe the recording files from the start, which conflicts with the architecture's rule that chat changes nothing in how live text is made. Found in phase 4's code review. Decide: accept "from now" and correct the functional spec and UI text, or schedule catch-up work.
  - **Decision (2026-10-29):** fix — turning the live transcript on mid-recording, from chat or from Settings, always catches up from the start of the recording, with no button. The live transcript reads the recording files from 0:00 up to that moment and hands them to its existing catch-up (the path that already catches up on audio waiting in the pump, with "Catching up…"), then continues live. While it catches up, chat answers from what is transcribed so far and says how far that reaches. functional_spec.md already describes this for chat's Turn On; extend it to every mid-recording start.
  - **Why:** user: "if you turn on chat, you want the whole transcript … I think catch up should work." The catch-up exists but only has audio received while a session existed; with the live transcript off, the earlier audio is only in the recording files. Feeding the files into the same catch-up is the one new piece. Approved by the user over an earlier proposal to start from now.
  - **Route:** task run 2
